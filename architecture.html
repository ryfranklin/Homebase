Home·base personal AI pipeline AWS · Anthropic-native single-tenant seed, multi-tenant ready

An authenticated web GUI, an SSH plane, and a Slack bridge over a private knowledge base. Several ways in, one agent core. The agent answers by running a tool-use loop over knowledge-base search and the live connectors, and streams its response token by token. Retrieval is semantic with reranking; connectors are live and write-gated; the perimeter is layered and a Bedrock Guardrail governs every model call. Every value shown here is a placeholder.

System context and the access planes

The GUI door, the SSH door, and the Slack bridge all reach the same agent runtime. Nothing shares long-lived keys.

GUI plane web

React SPA on CloudFront (WAF). Cognito + Google login (PKCE, no secret). Streams from a Lambda BFF over a Function URL (SSE).

Thin chat CLI ssh-side

Containerized terminal client on Fargate, reached only via ECS Exec over SSM. No repo access, no long-lived credentials. Invokes the agent via its task role.

Workstation ssh-side

Isolated EC2 dev/ops box, SSM-only (no key pair, no inbound, no public IP), encrypted volumes, scoped non-admin role, auto-stop when idle.

Slack bridge slack-side

A slack-bolt Socket Mode service on Fargate, VPC-internal with no inbound (outbound WebSocket only). Resolves the sender's verified email, gates on an allow-list, invokes the agent via its task role, and answers in a thread.

Agent core

Claude on Bedrock via AgentCore Runtime, running a tool-use loop over knowledge-base search and the connector read tools, streaming its answer token by token (SSE end to end). Knowledge-base answers cite their sources; AgentCore Memory (short + long term); OTEL observability to CloudWatch.

Identity model

User (sub) and tenant (custom:tenant_id) are explicit end to end: JWT claims, memory actor id, and connector token namespace. Single-tenant today, no one-way doors.

Infrastructure

Terraform across fourteen stacks: remote-state bootstrap, foundation (VPC/KMS/budget), storage, identity, retrieval, agent, api, web, ssh-chat, workstation, connectors, monitoring, mission-control (the execution engine on Fargate + RDS), and slackbot (the optional Slack door). A vault-worker Fargate service owns the git source of truth.

Factual note. Hybrid (dense + keyword) search is not available on Amazon S3 Vectors: it is semantic-only, and rerank is a query-time step independent of the store. The compensation ladder (over-retrieve, then Bedrock Rerank, plus metadata filters) carries exact-term and scoped queries on a semantic index.

The gated hybrid seam ADR-002

If hybrid becomes a hard requirement, the fallback is Amazon OpenSearch Serverless (which supports HYBRID and richer filters). It is a marked, variable-gated seam in the retrieval stack, chosen on evidence from the eval harness, not built by default.

The eval decides evidence

A retrieval eval harness scores hit rate and MRR with rerank off vs on. A CI regression gate guards the retrieval code on synthetic fixtures; absolute quality on the real corpus is the separate live eval that decides the ADR-002 question.

Layered security perimeter

Two doors, two distinct authorization models.

GUI door — defense in depth

1CloudFront + WAF — managed rule groups, rate limiting, optional geo allowlist. Private S3 origin via OAC (no public bucket).
2Origin shared-secret header — CloudFront injects X-Origin-Secret; the BFF refuses requests without it, so direct-to-origin calls that bypass the WAF are dropped. Rotated via Secrets Manager.
3In-function Cognito JWT — the BFF validates RS256 against the pool JWKS (issuer, audience, expiry), no API Gateway authorizer.
4Per-user and per-tenant scoping — identity is taken from the token (sub, custom:tenant_id); a request naming another tenant or user is rejected, not honored.

SSH door — the IAM / SSM boundary

ANo network path in — no key pair, no inbound ports, no public IP. Reachability is exclusively SSM (Session Manager / ECS Exec), auditable and KMS-encrypted.
BLeast-privilege roles — the chat CLI task role can invoke only the agent runtime. The workstation instance role is NOT admin; broad actions come from assuming task-specific roles for short-lived credentials.
CNo long-lived keys on disk — credentials come from the instance/task role and short-lived assume-role. Dotfiles secrets are pulled from Secrets Manager at session start, never baked in.

Slack door — an allow-list over Socket Mode

S1No inbound — Socket Mode is an outbound WebSocket, so the bridge runs VPC-internal with NAT egress only: no public endpoint, no webhook, no request signing to verify.
S2Verified-email allow-list — the sender's Slack email must be on a by-hand SSM SecureString; an unknown or email-less user is refused. The identity presented to the agent is that verified email.
S3Least-privilege task role — the bridge can invoke only the agent runtime and read the allow-list, mirroring the chat CLI. The two Slack tokens are injected from Secrets Manager, never baked in.

Every door — one guardrail at the model call

A Bedrock Guardrail is applied to every model (Converse) call, so the same governance protects all doors (GUI, CLI, Slack) at the model boundary: prompt-attack detection on input, content filters (hate, insults, sexual, violence, misconduct), and a denied topic (credential exfiltration). PII detection is deliberately off for a personal assistant.
Every environment-specific or secret value is an input (Terraform variable, env var, Secrets Manager, or SSM Parameter Store), never a literal. Terraform is never auto-applied by an agent; a human runs apply.

Connectors: live, read-first, write-gated, never indexed

Six live integrations. Each is a shim the agent calls as a tool; AgentCore Identity holds a per-user OAuth token. Homebase authenticates each independently.

Gmail read-first

Search messages (read). Send is a gated write.

Google Calendar read-first

List events (read). Create event is a gated write.

Google Drive read-first

Search files (read). Modify file is a gated write.

Slack read-first

Read a channel by name or id (read). Post is a gated write. A dedicated Homebase app, own scopes.

Jira read-first

Search issues with JQL, site id resolved automatically (read). Create issue is a gated write.

Confluence read-first

Search pages with CQL (read). Shares one Atlassian app with Jira via a unioned scope set.

Write gate confirm

Any write (send, post, create, modify) returns a confirmation contract instead of executing. Only a re-invocation with the matching token proceeds. The gate lives at the tool layer, so the GUI and the SSH CLI both inherit it. Only read tools are offered to the agent.

Identity per-user

OAuth tokens live in AgentCore Identity, keyed by the caller's tenant and connector. No tokens, client ids, or workspace ids in code; the agent reaches a connector with only the tenant it already carries. Independent auth, no borrowed tokens.

Never indexed ADR-004

Connector data is fetched live per query and is never written into the corpus / S3 Vectors store. There is no connector-to-corpus ingestion path.

Planning and execution: Flight Planner to Mission Control

Homebase is the ground station: it plans and observes. Mission Control is the execution engine. The seam is data (an open flight plan in git), not a proprietary API.

Flight Planner plan

The agent runs an AI-DLC INCEPTION interview (intent → requirements → acceptance criteria → a units work-list), grounded on the vault and Confluence. Plans persist as versioned notes in the git vault; every criterion is a proposal for the human review gate.

Mission Control execute

A durable, cost-metered orchestrator for coding agents (its own repo), deployed VPC-internal on Fargate + RDS. Each unit runs as an isolated git-worktree task, Claude via Bedrock, verified against the target repo's own checks plus its acceptance criteria, then paused at a go/no-go gate, with priced per-step telemetry.

Mission deck observe

The ground-station view in the GUI: launch a unit, watch its live telemetry (node transitions + cost), and drive the gate. One brain, five front doors: Vault · Chat · Plan · Mission · Slack.

The seam

The BFF reaches Mission Control over Cloud Map on the private VPC with a bearer token. A flight-plan unit maps to a run (task_type from the AI-DLC phase), carrying the unit's acceptance criteria so Mission Control judges the build against its own definition of done before the gate; telemetry streams back as SSE. See docs/mission-control-seam.md.

Design in, tickets out

Confluence pages become grounded plan sources; a cleared plan materializes into a Jira epic + a story per unit through the write-gated connector. Traceability: ticket → waypoint → AC → source. See docs/confluence-jira-integration.md.

State, security and ops

Storage S3

Private corpus bucket (KMS), the SPA static bucket (OAC), and the remote-state bucket. Amazon S3 Vectors holds the retrieval index.

Secrets & config KMS

KMS CMKs per stack; Secrets Manager for the rotating origin secret, OAuth client secrets, and workstation secrets; SSM Parameter Store for non-secret config (SecureString for the allow-list).

Access no SSH

Workstation and CLI are reached only through SSM (Session Manager / ECS Exec) — no key pair, no inbound, no public IP.

Observability CloudWatch

Encrypted log groups, dashboards, and spend / uptime alarms to an SNS topic; OTEL traces from the agent.

Network posture. CloudFront (WAF + origin secret) is the only public ingress. The BFF and shim Lambdas are not VPC-attached — they reach AWS APIs over the AWS network.
