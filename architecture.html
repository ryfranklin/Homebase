Home·base personal AI pipeline AWS · Anthropic-native single-tenant seed, multi-tenant ready

An authenticated web GUI plus an SSH plane over a private knowledge base. Two ways in, one agent core. The agent answers by running a tool-use loop over knowledge-base search and the live connectors, and streams its response token by token. Retrieval is semantic with reranking; connectors are live and write-gated; the perimeter is layered. Every value shown here is a placeholder.

System context and the two access planes

The GUI door and the SSH door both reach the same agent runtime. Nothing shares long-lived keys.

GUI plane web

React SPA on CloudFront (WAF). Cognito + Google login (PKCE, no secret). Streams from a Lambda BFF over a Function URL (SSE).

Thin chat CLI ssh-side

Containerized terminal client on Fargate, reached only via ECS Exec over SSM. No repo access, no long-lived credentials. Invokes the agent via its task role.

Workstation ssh-side

Isolated EC2 dev/ops box, SSM-only (no key pair, no inbound, no public IP), encrypted volumes, scoped non-admin role, auto-stop when idle.

Agent core

Claude on Bedrock via AgentCore Runtime, running a tool-use loop over knowledge-base search and the connector read tools, streaming its answer token by token (SSE end to end). Knowledge-base answers cite their sources; AgentCore Memory (short + long term); OTEL observability to CloudWatch.

Identity model

User (sub) and tenant (custom:tenant_id) are explicit end to end: JWT claims, memory actor id, and connector token namespace. Single-tenant today, no one-way doors.

Infrastructure

Terraform across twelve stacks: remote-state bootstrap, foundation (VPC/KMS/budget), storage, identity, retrieval, agent, api, web, ssh-chat, workstation, connectors, monitoring.

Factual note. Hybrid (dense + keyword) search is not available on Amazon S3 Vectors: it is semantic-only, and rerank is a query-time step independent of the store. The compensation ladder (over-retrieve, then Bedrock Rerank, plus metadata filters) carries exact-term and scoped queries on a semantic index.

The gated hybrid seam ADR-002

If hybrid becomes a hard requirement, the fallback is Amazon OpenSearch Serverless (which supports HYBRID and richer filters). It is a marked, variable-gated seam in the retrieval stack, chosen on evidence from the eval harness, not built by default.

The eval decides evidence

A retrieval eval harness scores hit rate and MRR with rerank off vs on. A CI regression gate guards the retrieval code on synthetic fixtures; absolute quality on the real corpus is the separate live eval that decides the ADR-002 question.

Layered security perimeter

Two doors, two distinct authorization models.

GUI door — defense in depth

1CloudFront + WAF — managed rule groups, rate limiting, optional geo allowlist. Private S3 origin via OAC (no public bucket).
2Origin shared-secret header — CloudFront injects X-Origin-Secret; the BFF refuses requests without it, so direct-to-origin calls that bypass the WAF are dropped. Rotated via Secrets Manager.
3In-function Cognito JWT — the BFF validates RS256 against the pool JWKS (issuer, audience, expiry), no API Gateway authorizer.
4Per-user and per-tenant scoping — identity is taken from the token (sub, custom:tenant_id); a request naming another tenant or user is rejected, not honored.

SSH door — the IAM / SSM boundary

ANo network path in — no key pair, no inbound ports, no public IP. Reachability is exclusively SSM (Session Manager / ECS Exec), auditable and KMS-encrypted.
BLeast-privilege roles — the chat CLI task role can invoke only the agent runtime. The workstation instance role is NOT admin; broad actions come from assuming task-specific roles for short-lived credentials.
CNo long-lived keys on disk — credentials come from the instance/task role and short-lived assume-role. Dotfiles secrets are pulled from Secrets Manager at session start, never baked in.
Every environment-specific or secret value is an input (Terraform variable, env var, Secrets Manager, or SSM Parameter Store), never a literal. Terraform is never auto-applied by an agent; a human runs apply.

Connectors: live, read-first, write-gated, never indexed

Six live integrations. Each is a shim the agent calls as a tool; AgentCore Identity holds a per-user OAuth token. Homebase authenticates each independently.

Gmail read-first

Search messages (read). Send is a gated write.

Google Calendar read-first

List events (read). Create event is a gated write.

Google Drive read-first

Search files (read). Modify file is a gated write.

Slack read-first

Read a channel by name or id (read). Post is a gated write. A dedicated Homebase app, own scopes.

Jira read-first

Search issues with JQL, site id resolved automatically (read). Create issue is a gated write.

Confluence read-first

Search pages with CQL (read). Shares one Atlassian app with Jira via a unioned scope set.

Write gate confirm

Any write (send, post, create, modify) returns a confirmation contract instead of executing. Only a re-invocation with the matching token proceeds. The gate lives at the tool layer, so the GUI and the SSH CLI both inherit it. Only read tools are offered to the agent.

Identity per-user

OAuth tokens live in AgentCore Identity, keyed by the caller's tenant and connector. No tokens, client ids, or workspace ids in code; the agent reaches a connector with only the tenant it already carries. Independent auth, no borrowed tokens.

Never indexed ADR-004

Connector data is fetched live per query and is never written into the corpus / S3 Vectors store. There is no connector-to-corpus ingestion path.
